**UUID**: `f1720d60-a7a9-4306-a003-11948f9e077c`**总长度**: 38 字节（对应 4 字节头 + 1 个 34 字节条目）

| ----------- | -------------------- | ------- | ------------------------------------------------------------ |
| 00h         | **Log Header**       | 4 字节  | 包含 `Total Number of Entries`（10位）和 `Header ID` 等公共信息。 |

#### 1.1 DDR5 Error Check Scrub (ECS) Log 条目解析

该日志由 4 字节头和多个 34 字节的 **ECS Log Entry** 组成。

**ECS Log Entry (34 字节)**：

| 偏移 | 字段名称            | 长度    | 说明                                    |
| ---- | ------------------- | ------- | --------------------------------------- |
| 00h  | **Log Flags**       | 1 字节  | 包含条目有效位、错误溢出位等信息。      |
| 01h  | **DRAM Address**    | 6 字节  | 指向发生 ECS 错误的物理地址或 DPA。     |
| 07h  | **ECS Error Count** | 2 字节  | 记录该地址/区域检测到的纠正性错误总数。 |
| 09h  | **ECS Threshold**   | 2 字节  | 当前配置的报警阈值。                    |
| 0Bh  | **Vendor Specific** | 23 字节 | 供应商特定的详细错误上下文。            |

#### 2.1 Media Test Capability Log 条目解析

该日志由 16 字节头和多个 16 字节的 **Test Capability Entry** 组成。

**Test Capability Entry (16 字节)**：

| 偏移 | 字段名称              | 长度    | 说明                                                   |
| ---- | --------------------- | ------- | ------------------------------------------------------ |
| 00h  | **Test Algorithm ID** | 1 字节  | 算法标识（如：01h=WRC, 02h=Checkerboard, 03h=MARCH）。 |
| 01h  | **Capability Flags**  | 1 字节  | Bit 0: 是否支持指定 DPA；Bit 1: 是否支持后台运行。     |
| 02h  | **Expected Time**     | 2 字节  | 每 GB 介质完成该测试所需的预期时间（秒）。             |
| 04h  | **Reserved**          | 12 字节 | 保留。                                                 |

### 4. Media Test Results Long Log

**UUID**: `c1fe0b3e-7a00-448e-a24e-a6aabbfe587a`**总长度**: 5472 字节（对应 16 字节头 + 变长测试摘要与错误签名）

该日志结构较为复杂，由 16 字节头、48 字节的测试执行摘要（Summary）和 80 字节的详细错误签名（Error Signature）组成。

| 偏移 (字节) | 字段名称                    | 长度         | 说明                                                         |
| ----------- | --------------------------- | ------------ | ------------------------------------------------------------ |
| 00h         | **Log Header**              | 16 字节      | 包含错误签名总数及长日志特定状态位。                         |
| 10h         | **Test Execution Summary**  | 48 字节      | 每个测试任务的详细摘要，包含测试耗时、覆盖范围等。           |
| 40h+        | **Error Signature Entries** | 每个 80 字节 | 记录测试中发现的具体硬件错误，包含失败的 DPA 地址、错误类型及组件标识符。 |



#### 4.1 Media Test Results Long Log 递归解析

长日志结构最为复杂，包含一个 **Execution Summary** 和多个 **Error Signatures**。

**A. Test Execution Summary (48 字节)**

每个测试任务的基础摘要。

| 偏移 | 字段名称           | 长度    | 说明                                                    |
| ---- | ------------------ | ------- | ------------------------------------------------------- |
| 00h  | **Task Status**    | 2 字节  | 当前测试任务的详细状态码。                              |
| 02h  | **Error Count**    | 2 字节  | 本次测试发现的错误签名条目总数（即下方 B 表的条目数）。 |
| 08h  | **Start/End Time** | 16 字节 | 测试起止时间。                                          |
| 18h  | **Test Range**     | 16 字节 | 本次测试覆盖的起始 DPA 和 长度。                        |

**B. Error Signature Entry (80 字节)**

递归嵌入在长日志中的具体错误详情。

| 偏移 | 字段名称         | 长度    | 说明                                                         |
| ---- | ---------------- | ------- | ------------------------------------------------------------ |
| 00h  | **Failed DPA**   | 8 字节  | 发现故障的具体设备物理地址。                                 |
| 08h  | **Error Type**   | 2 字节  | 错误性质（如：纠正性错误、不可纠正错误、巡检发现）。         |
| 0Ah  | **Component ID** | 16 字节 | **递归嵌入：** 标识故障的物理实体（遵循 PLDM 实体标识符，详见对话历史）。 |
| 1Ah  | **Vendor Data**  | 54 字节 | 供应商定义的原始错误寄存器快照或诊断数据。                   |
